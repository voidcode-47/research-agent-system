# 论文诊断与优化工作台

本地运行的论文辅助工具：上传 PDF / Word 后完成需求确认、四维诊断、相似论文检索、段落级改写与 Word / PDF 导出，并提供参考文献调研与综合报告生成。

只做诊断、建议与局部改写，不代写整篇论文，不编造数据与引用。

## 功能

### 论文工作台（五步向导）

1. **上传 PDF / Word**：接受 `.pdf` 与 `.docx`，校验文件头与大小（≤50MB；PDF ≤200 页，Word 页码按字数估算）；旧版 `.doc` 与扫描版 PDF 会给出明确提示。上传解析显示实时进度，可随时取消且不保存半成品。
2. **需求确认**：根据论文标题、摘要与章节自动预填层次、格式与去 AI 味强度，核对后确认即可；确认后才能进入诊断。
3. **四维诊断**：论文层次、内容可实现性、正文格式、AI 率四个固定维度评分，并给出可执行修改建议；格式检查与优先修改项在本地完成，不调用模型。云端模型维度最多三路并行，本地模型依次执行；每完成一维就显示该项结果，未完成项保留占位。AI 率一栏支持中文与英文论文，检测学术写作特征并估算 AI 生成率。诊断过程显示实时进度条，可随时取消（已完成维度会保留）。AI 生成率基于规则估算，仅作自查参考。
4. **相似论文**：通过 Crossref / OpenAlex 检索相关文献，辅助判断选题重合度与创新点位置；检索过程显示进度并可取消，结果缓存 7 天。
5. **段落改写**：先基于全文生成全局改写方针（术语统一、跨段重复句式、章节过渡），再选择正文段落按去 AI 味 / 学术化 / 精简等模式套用该方针改写，展示差异后可逐段采纳。支持勾选多个正文段落批量改写（单次最多 8 段），批量与单段改写均显示进度、可取消，完成后可逐段查看差异并采纳，也可“全部采纳成功段”一次保存为同一版本；任一段正文已变化则整批不保存，失败段不会保存。采纳时会校验该段正文是否仍是改写所依据的版本；若查看差异期间论文已被其他操作更新，会保留当前差异并提示冲突，不会覆盖新内容。
6. **论文问答**：围绕当前论文提问，答案会列出所依据的段落编号；点击编号可直接打开并查看对应原文。
7. **导出**：保留标题层级与正文结构，可导出可编辑 `.docx`、`.pdf`（本机中文字体嵌入）或《论文修改说明》`.docx`（诊断结论、问题清单与逐段前后对照）。文件名沿用原论文名，默认推荐与上传格式一致的导出格式。

### 版本整理与备份恢复

- **整理旧版本**：手动把较早版本压缩进 `versions/archive.json.gz`，始终保留原始版本 v0、当前版本和最近 N 个版本；归档版本仍可通过历史版本接口读取，不会直接丢失。
- **备份数据**：下载单篇论文的 `.zip` 备份，包含原文、需求、诊断、相似论文缓存、改写方针与全部版本（含归档版本），不包含导出文件。
- **恢复备份**：上传本应用生成的 `.zip`，校验清单、文件路径、大小、SHA-256 与 JSON 结构后，恢复为一篇**新论文**；不会覆盖或修改现有论文。

再次打开工作台时，会自动恢复上次查看的论文与步骤，无需重新选择。论文下拉框支持按标题、文件名或论文 ID 搜索，并按 `offset/limit` 分页加载“更多”；索引有效时不会为每次搜索重新扫描论文目录。

### 前端资源版本

前端保持原生 HTML/CSS/JS，不引入打包器或框架。修改 `web/` 下的 CSS/JS 后运行：

```bash
.venv\Scripts\python.exe scripts\build_frontend.py
```

脚本会为 `index.html` 引用的本地资源写入 12 位内容哈希（`?v=...`），生成 `web/asset-manifest.json`，并用 `node --check` 校验 JS 语法（无 node 时跳过语法检查）。构建幂等；服务启动时若发现 `index.html` 的版本与文件内容不一致，会记录警告并提示重新构建。

### 参考文献调研

- 输入论文方向 → 并行检索 Crossref / OpenAlex → 按相关度去重排序展示文献。
- 基于文献题录与摘要生成结构化调研报告（背景、现状、方法、实验、争议、研究问题与假设、研究设计、数据获取计划与建议），自动附参考文献列表。
- 研究方案与数据获取计划会明确研究对象、方法步骤、对照/基线、评价指标、数据来源与获取步骤、关键变量与字段、样本/时间范围、质量检查、合规与伦理注意事项及主数据源不可用时的备选方案；信息不足时会标明需要补充检索或人工核验的部分。
- 实时进度条与阶段日志，可随时停止调研；完成后支持追问、下载 Markdown / Word、历史报告预览与管理。

### 设置

- 「设置 → 工作台外观」提供纸白、月墨、雾蓝、鸢尾四套主题，侧栏色点可快速切换。主题同时改变配色、字体、圆角和界面层次，并在当前浏览器记住选择。
- 页面包含持续循环的纸页、校准滑杆、诊断雷达、引用网络、改写笔迹与轨道动画。可在侧栏或外观设置中关闭；系统启用“减少动态效果”时自动静止，切换到后台标签页时自动暂停。
- 四套主题另有覆盖整个页面的环境动画：纸白飘叶、月墨星光与流星、雾蓝玻璃水滴、鸢尾落花。雾蓝使用少量清透大水滴，带不规则轮廓、边缘高光和淡水痕，持续滑落，大水滴流速更快。环境层不拦截点击；关闭动画后隐藏。系统默认减少动态效果时，可通过动画开关手动开启环境动画。
- 全站使用同一个模型。管理员保存服务后，可在「设置 → 模型服务与协议」中选择服务和模型，再点「设为当前模型」。
- 自定义服务支持 DeepSeek、智谱 GLM、通义千问预设，也可手动输入 Base URL，并选择 OpenAI 兼容、Anthropic Messages 或 Gemini 协议；还支持本地 Ollama 和 LM Studio。
- API Key 只写入本地 `.env`，不回传前端、不进入仓库。

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python server.py
```

浏览器访问 <http://localhost:8501>。也可双击 `start.bat` 启动。

首次使用请在「设置 → 模型服务与协议」中配置服务并选定当前模型，再从侧栏测试连接。

### 管理员账号

- 左侧边栏「管理员登录」可登录；管理员可修改模型配置，且不受每日调用额度限制。
- 普通用户只能使用管理员设定的模型，设置页为只读。
- 首次启动会自动生成随机密码，保存在本机 `data/admin_credentials.txt`；登录后请妥善保存并删除该文件。
- 管理员登录后可在设置页修改密码；密码文件只保存带盐哈希，API Key 不写入服务元数据文件。
- 登录状态保存在 `data/admin_sessions.json`（仅存令牌哈希），有效 7 天，重启服务不会掉线。
- 也可在 `.env` 中设置 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 指定初始账号（优先级高于本地文件）。首次修改密码后会清除 `.env` 中的明文初始密码。

### 模型服务与协议

- 点击「新增自定义服务」并选择厂商预设可自动填写 Base URL，也可以手动填写服务地址。每套服务保存自己的 API Key。
- 点击「添加模型」可逐条输入模型 ID，选择其中一个作为默认模型；已有服务可以继续编辑模型列表。
- 添加模型后，可直接点击服务列表中的「使用此模型」切换，当前模型有明确标识；切换仅影响新任务。段落改写会校验原文语言，错误翻译会自动纠正重试一次，仍不符合则报错，不展示错误翻译作为可采纳结果。云端批量改写最多三段并行，本地模型依次处理。
- 服务元数据保存在 `data/custom_providers.json`，密钥写入本机 `.env`。普通用户只看到当前模型。

## 项目结构

```
server.py              FastAPI 入口、文献调研与报告接口
api/paper.py           论文工作台 API（上传/诊断/相似/改写/导出）
paper/                 PDF / Word 解析、持久化、诊断、改写、导出、备份恢复
rules/                 格式规则与去 AI 味规则引擎
config/                全局配置、论文 schema、提示词
llm/                   统一 LLM 工厂、OpenAI 兼容实现与多协议适配
tools/academic_search   Crossref / OpenAlex 检索
utils/                 偏好、配额、guard、日志、前端资源哈希、Markdown→Word
web/                   原生 HTML/JS SPA（无框架）与资源版本清单
scripts/               构建脚本（前端资源哈希）
data/                  本地数据（论文、报告、偏好；已 gitignore）
```

## 数据与隐私

- 论文 PDF、诊断结果、改写记录与报告均保存在本地 `data/`，不会上传到第三方服务（模型推理请求除外）。
- 备份 zip 在本地生成，包含论文原文与全部持久化状态；恢复只在本地校验和写入，始终创建新论文 ID，不覆盖现有数据。
- 调用云端模型时，仅发送当前任务所需的文本片段；论文正文以 `<paper_text>` 数据块包裹，明确与指令隔离。
- `.env`、`data/papers/`、`data/reports/`、`data/ui_prefs.json`、`data/quota.json` 均已 gitignore。
- 审计日志不记录论文正文。

### 一致性与恢复

- 版本文件只追加、不覆盖；上传时的解析结果与 v0 始终保留，可在历史版本中回看。
- 版本整理是手动操作：只把 v0 与当前版本之外的较早版本合并压缩到一个归档文件，写入成功后才会删除原始版本文件；归档内容仍可由历史版本读取。整理不是自动清理，运行中途不会自行压缩版本。
- 恢复备份先写入论文目录下的临时暂存目录，全部校验通过后才重命名为新的论文 ID；校验失败会清理暂存目录，不留下半成品论文。索引随后重建，丢失时会由论文目录自愈。
- 备份不包含 `exports/` 中的生成文件，也不包含服务实例锁和任务日志；恢复不会恢复中断的后台任务。
- 单进程内所有“读-改-写”操作使用同一把可重入锁串行化；JSON 先写入唯一临时文件，`fsync` 后再原子替换。索引 `index.json` 只是缓存，丢失、损坏或与论文目录不一致时会从各论文的 `meta.json` 自动重建。
- 诊断开始时会固定当前正文版本和已确认需求；诊断期间论文正文或需求发生变化时，旧结果不会写回当前论文，任务会提示重新诊断。
- 删除论文会先取消该论文的排队或运行任务，并在删除窗口拒绝登记新任务；迟到的诊断、相似论文或改写结果不会重新创建目录或写入已删除论文。
- 服务启动时会在论文数据目录获取 `_server.lock` 独占文件锁；若另一个服务进程正在使用同一目录，则拒绝启动并提示停止旧实例或配置不同的 `PAPER_DATA_DIR`。这防止两个进程同时写入，但不是多 worker 支持：存储层仍假定单进程，多进程并发部署不在支持范围内。

### 后台任务

- 上传、诊断、相似论文、改写与方针生成统一进入有界任务队列：默认最多 3 个并发执行、12 个排队或运行；超过上限会提示稍后重试，不会无限开线程。
- 并发数 `PAPER_TASK_WORKERS`（1-16）、活动任务上限 `PAPER_MAX_ACTIVE_TASKS`（1-100）和已结束任务保留时长 `PAPER_TASK_RETENTION_MINUTES`（0-525600 分钟）可通过 `.env` 配置，启动时校验范围，修改后需重启。保留清理在下次创建任务时执行；设为 0 表示不按时间清理，但仍受 100 条任务硬上限约束。
- 任务先显示“排队中”，开始执行后转为运行中；相同论文、相同参数的重复提交会复用正在排队或运行的任务，避免重复模型调用。
- 取消规则：排队中的任务立即取消，上传任务会清理未完成的临时文件；运行中的任务在当前步骤结束后停止，已完成的诊断维度会保留。任务到达完成、失败或取消后状态不再改变。
- 活动任务的最小元数据（任务 ID、类型、论文 ID、状态与时间）会原子写入论文数据目录下的 `_task_journal.json`，不包含正文、改写结果或日志。
- 服务重启时，日志中尚未完成的任务会恢复为“失败”，并提示“服务重启导致任务中断，请重新发起”，随后清空日志；中断的模型调用不会自动继续或重试。没有日志或日志损坏时按任务不存在处理，需要重新发起。已结束任务不写入日志。改写结果在采纳前不落盘。
- 任务状态通过 SSE（`/api/paper/{paper_id}/tasks/{task_id}/events`）推送，终态发送 `event: end` 后关闭；浏览器不支持 SSE、连接中断或任务因服务重启失效时，前端自动回退到状态轮询。SSE 只推送任务状态，不代替任务结果落盘。

### 额度与重试

- 每日额度由 `.env` 的 `DAILY_QUOTA` 设置，0 表示当日不可调用；修改后需重启。
- 一次逻辑模型调用只计 1 次额度；网关内部的格式重试不会重复扣减。
- 提供商报错、限流、本地未加载模型或连接失败，且没有任何可用模型输出时，本次额度会自动退还。
- 模型已返回内容但 JSON 或结构校验失败时保留这次消耗，因为提供商已产生实际输出。
- 排队中取消不消耗额度；模型请求发出后再取消，已执行的调用不退还。管理员不限额度，也不写入配额。
- 任务创建时按最大调用次数预留额度：诊断按所选模型维度数（格式检查不占额度，完整诊断最多 3 次）、单段改写与方针生成各 1 次、批量改写按所选段落数。额度不足时直接返回 429，不创建任务，也不会发起模型调用；相同任务被复用时不重复预留。
- 额度按每次逻辑调用记账，同时从该任务的预留中扣减。任务完成、失败或取消时释放未使用的预留；提供商报错且没有可用输出时，退还的额度回到本任务预留。额度快照中的 `reserved` 表示当前活动任务的预留总量，`remaining` 已扣除预留。
- 预留保存在服务进程内存中，只对当前进程有效；服务重启后预留消失，已发生的调用仍保留在 `quota.json` 的 `used` 中。这不是跨进程的分布式配额：多进程部署仍不在支持范围内。
